# 역할별 화면 목록

## 1. 공통 원칙

- 반응형 웹, API `/api/v1`, camelCase 계약을 사용한다.
- 모든 화면은 진입조건, 빈 상태, 오류 상태, 중복클릭 방지, 서버상태 재조회를 정의한다.
- 동적 요청필드는 관리대장 스키마로 렌더링한다.
- 신뢰점수 대신 “신규·평가중”을 표시한다.
- 채택 전 Provider 화면에는 상세주소·연락처 데이터 자체를 반환하지 않는다.

## 2. 고객

| ID | 화면 | 핵심 기능 |
|---|---|---|
| `CUS-001` | 홈/카테고리 | `ACTIVE+ONE_TIME` 카테고리 |
| `CUS-010` | 요청 작성 | 동적필드, 주소, 파일, 임시저장·공개 |
| `CUS-020` | 내 요청 | 핵심 상태와 파생 `hasQuotes/decisionPending` |
| `CUS-030` | 견적 비교 | 총액, VAT, 항목, 범위, 일정, 보증, revision |
| `CUS-031` | 채택 확인 | 최종 revision 확인·단일 채택 |
| `CUS-040` | Transaction 상세 | 거래번호, Provider, 상태, 채택 후 정보 |
| `CUS-050` | 완료 확인 | 작업내용, 실제금액, 적용 정책별 사진·역할 증빙, 정상/보완/분쟁 |
| `CUS-HIS-001` | 수리·서비스 이력 | 기간·카테고리·Provider·자산·A/S 필터 |
| `CUS-HIS-002` | 시설·제품 목록/등록 | 최소정보 등록·조회 |
| `CUS-HIS-003` | 시설·제품 이력 | 거래연결, 완료/A·S 시간순 조회 |
| `CUS-AS-001` | A/S 접수/목록 | 원 거래, 보증 내/외, 증상 |
| `CUS-AS-002` | A/S 상세 | 접수→진행→완료와 증빙 |

필수 오류/빈 상태: 동적필드 검증 실패, 후보 0명, 견적 0건/만료, 채택 충돌, 보완 revision, 이력 처리중, 접근권한 없음.

## 3. Provider

| ID | 화면 | 핵심 기능 |
|---|---|---|
| `PAR-001` | 대시보드 | 새 배포요청, 견적, 진행 Transaction, 완료/A·S |
| `PAR-010` | 프로필/승인상태 | PENDING/APPROVED/REJECTED/SUSPENDED |
| `PRO-CAT-001` | 공급 카테고리 | `ACTIVE+ONE_TIME` 선택 |
| `PRO-AREA-001` | ProviderServiceArea | 카테고리별 시군구 다중선택 |
| `PRO-NOTI-001` | 맞춤 요청함 | 배포된 요청, 마스킹 상세 |
| `PAR-030` | 견적 작성 | 총액/VAT/항목/범위/보증 |
| `PAR-031` | 견적 revision | 채택 전 수정이력/철회 |
| `PAR-040` | Transaction 상세 | 작업시작, 거래정보 |
| `PAR-050` | 작업 완료 | 실제금액, 작업내용, Transaction 정책 스냅샷 기반 필수사진 수·역할 안내/검증 |
| `PAR-HIS-001` | 작업·수리 이력 | 본인 수행 거래·A/S |
| `PAR-AS-001` | A/S 목록/상세 | 해당 거래 접수, 진행·완료·증빙 |

타 Provider 데이터, 비배포 요청, 고객 전체 시설 이력은 접근하지 못한다.

`PAR-050`은 `requiredPhotoCount=0`일 때 사진 없이 제출할 수 있어야 하며 2/5와 향후 값은 동적으로 최소 개수를 표시한다. 정책에 역할이 있으면 `BEFORE/AFTER/DETAIL/SERIAL/DAMAGE` 등의 역할별 입력 슬롯과 충족상태를 표시한다.

| `ADM-AUD-001` | 감사로그 | 전후값·사유·행위자 |

## 5. 제외 화면

AI, 구독, GPS/QR, PG/결제, 월말정산, 인테리어, 모바일 앱, 수수료/충전금, 신뢰점수 정책, 복잡한 예약, 분쟁 운영 전체 화면은 MVP 내비게이션에 만들지 않는다.
